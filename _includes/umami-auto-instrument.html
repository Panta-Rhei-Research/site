{%- comment -%} Auto-instruments tile-grid and recurring-CTA surfaces with Umami event attributes at runtime, for elements that the layout / markdown body did not wire explicitly. Why a runtime instrumentation pass (rather than only inline data-umami-event attributes): the v2-tile lane-grids appear in 80+ markdown files as raw HTML anchors. Inline editing each one is slow and drift-prone. Umami reads data-umami-event* attributes at click time, so setting them via JS at page-ready is equivalent to having them in the source HTML — and it covers every current and future tile uniformly. Surfaces auto-instrumented: - → nav.tile.{destination-slug} - → nav.card.{destination-slug} - aside.right-rail a.artifact-link → nav.rail.{destination-slug} - .section-ctas / .homepage-section .btn-group anchors (.btn-primary | .btn-secondary | .btn-ghost), excluding .hero-card → cta.section.{destination-slug} Naming derivation: destination-slug = anchor.pathname stripped of leading/trailing "/", segments joined with "-", truncated to ≤30 chars. Example: "/results/predictions/browse/" → "results-predictions-browse". "/" → "home". Off-site / fragment-only links are skipped. Location attribution: data-umami-event-location = current page's pathname slugified the same way Example: a tile on /results/ pointing to /results/predictions/ emits data-umami-event="nav.tile.results-predictions" data-umami-event-location="results" Skip rules: - Anchor already has data-umami-event set (inline / via cta-attrs.html) — leave it. - href is empty, "#", "javascript:", "mailto:", "tel:". - href is fully external (host !== current host) — outbound vendors are handled by cta-attrs.html where it's wired; out-of-scope tiles are rare. Doctrine: atlas/website/doctrine/umami-events.md (verb: nav, objects: tile|card|section). ≤50-char event name limit is enforced via slice + truncation in JS. {%- endcomment -%}
